-- Changed: Forwarding headers are believed only from a proxy listed in the new P202_TRUSTED_PROXIES environment variable (addresses, CIDR ranges, or `cloudflare` for Cloudflare's published ranges). Before, any visitor could send X-Forwarded-For, CF-Connecting-IP or X-Real-IP and be recorded at the address they chose, and X-Forwarded-Proto set the Secure flag of the session and p202vid cookies. Now the client is the connecting address unless that is a listed proxy, whose X-Forwarded-For is read from the right, so the click's address, its GEO and ISP, the duplicate-IP filter, the sign-in throttle and the public endpoints' rate limits all key on an address the visitor cannot choose, and behind a listed proxy each visitor has its own rate-limit bucket. CF-Connecting-IP and the other single-value headers are no longer read. An entry that cannot be read trusts no proxy and is logged. Upgrading: an install behind Cloudflare, a load balancer or a reverse proxy records the proxy's address for every visitor until its proxies are listed (the Coolify stacks list the private Docker ranges); a TLS-terminating proxy's X-Forwarded-Proto counts only once it is listed or the web server sets HTTPS itself, as the Docker image does.
app: Changed: Visitor addresses and HTTPS behind a proxy now come only from proxies listed in P202_TRUSTED_PROXIES. If your install is behind Cloudflare or a load balancer, list it (see the FAQ), or every click is recorded at the proxy's address.
