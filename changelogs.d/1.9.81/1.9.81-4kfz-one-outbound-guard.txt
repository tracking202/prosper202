# 4KFZ: one route for every guarded sender, an egress-proxy setting, and getData()/getUrl() held to the vendor host.
-- New: An egress proxy for servers that reach the internet only through one: define('P202_EGRESS_PROXY', 'http://proxy.example:3128'); in 202-config.php (https:// and a percent-encoded user:password@ are read too; the port is required). Export and LTV webhooks, traffic-source postbacks, Slack notices, syncs, the conversion destinations (Google Ads, GA4, ChatGPT Ads), Get LP Code's Check my page and the GeoIP download then go through it. They refused every proxy, so on such a server none of them could be delivered. Each is still checked by this server's outbound guard first, its host looked up here, and sent through a CONNECT tunnel to the address that passed, so the proxy is never asked to look up the name and a DNS answer that changes after the check moves nothing; TLS is still verified against the host name. Plain-http postbacks are tunnelled too, so the proxy must allow CONNECT to port 80 and any other port a postback URL names. An address only P202_WEBHOOK_ALLOW_NETWORKS admits (the operator's own network) is reached directly, as before. A value that does not read as a proxy URL (no port, a scheme other than http or https, anything after the port) holds all of them, naming the setting, and nothing is sent around the proxy instead: webhooks and postbacks wait and are retried. Requests to my.tracking202.com and to the operator's own services are unchanged and still use a proxy set in the server's environment.
app: New: Webhooks, postbacks, Slack notices, syncs and destinations can go out through an egress proxy (P202_EGRESS_PROXY in 202-config.php), still checked and pinned to the address that passed.
-- Fixed: Security. getData() and getUrl(), which fetch the update feeds, the hosting partners list and the TV202 feed, followed every redirect to any host and any address. They now fetch only from https://my.tracking202.com, follow a redirect (at most 3) only to that host over https, never follow a POST's redirect, and read at most 8 MB of an answer; anything else is refused and logged without its query.
