# Y9Q3, D7NS: the outbound guard's address lookup is held to each sender's own time.
-- Fixed: An address lookup that never got an answer could hold a request for much longer than its sender allows. Before a webhook, postback, Slack notice, sync or Get LP Code check is sent, this server looks its host up and checks every address. That lookup used the C library, which takes no time limit: a nameserver that never answered held a Slack notice (2 seconds), a postback (10) or a webhook (15) for resolv.conf's timeout times its attempts, per nameserver and per address family, before the sender's own clock even started. The lookup now asks resolv.conf's nameservers itself (after /etc/hosts, with its search list and ndots, falling back to TCP for a truncated answer), within what is left of the sender's time and at most 5 seconds; the request then has what the lookup left, to the millisecond. Each nameserver in turn gets its share of that time, so a dead first one never stops the second from being asked; once one address family has answered, the other is waited for half a second more at most; resolv.conf's single-request, use-vc and no-aaaa options, LOCALDOMAIN and RES_OPTIONS are honoured; and a server failure for one search-list name goes on to the next, as the C library does. A lookup that runs out says so ("was not looked up within 2 seconds") and is tried again later, as a name that does not resolve is. A name listed in /etc/hosts now answers with only the addresses listed there, in both families; before, DNS was still asked for its IPv6 address. Servers without a readable /etc/resolv.conf or /etc/hosts (Windows, or an open_basedir that leaves them out), or with PHP's socket functions disabled, keep the C library's lookup.
