-- Fixed: A report rebuild window (202_dataengine_job) left `processing` by a run that was killed, or whose release failed, was never rebuilt, and without curl no window after it either. A run now holds a server lock while it rebuilds a window; a window found claimed with its lock free is released and taken again by the next cron run, which logs it.
app: Fixed: A report rebuild interrupted part-way no longer stalls; the next cron run picks the window up again.
-- Fixed: The roll-up of one hour (202-cronjobs/dej.php) claimed, marked and released whichever rebuild window had that hour's bounds, so a failed hour released a window another run was rebuilding. The hour's roll-up no longer writes the windows: the run that took a window marks or releases it.
-- Fixed: A change to clicks made while the cron job was rolling their hours up again (202_dirty_hours) could be left out of the reports: the pass marked and deleted the queued hour by its id, with the newer request in it. The pass now takes an hour before it rolls it up and deletes it only if it is still taken, so an hour queued again meanwhile is rolled up by the next pass. An hour left taken by a pass that was killed is queued again, and one pass runs at a time.
app: Fixed: A change made while the reports were being refreshed is no longer missed by the refresh.
-- Fixed: Resetting a campaign's subids queued its report hours with INSERT IGNORE, which left an hour the pass had already taken as it was. It queues them as every other writer does.
-- Changed: GET /api/v3/system/dataengine `pending_dirty_hours` counts every hour not yet rolled up, one a pass has taken included.
