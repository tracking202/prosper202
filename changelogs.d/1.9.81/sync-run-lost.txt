-- Fixed: A server-side sync job whose worker process was killed stayed "running" forever and held its place in the pair's queue. A run PHP ends with a fatal error (out of time or memory) or an exit is now failed at once with PHP's message; a killed run is failed with `error_code` `sync_worker_lost` by the next read of the job, worker run or queued sync for the pair once it began 1,200 seconds ago and no process holds the job, with `written` counted from the writes its events logged. A cancel asked while it ran makes it cancelled.
app: Fixed: A sync job whose worker was killed is now marked failed, with what it had written, instead of staying "running" forever.
-- Fixed: A sync job that stopped on an error inside the server read "Internal server error". It now says it was an error inside this server, names its kind and the error log entry that has the detail, and carries `error_code` `sync_internal`; the detail is logged, never stored in the job.
app: Fixed: A sync job stopped by an error inside the server now says where its error log has the detail.
-- Changed: Sync stops name their cause: a record the sync cannot match or write (an empty name it matches by, a reference to a record the target lacks, a target record listed without an id) carries `error_code` `sync_record_unusable` and says what to change, and a pair already syncing carries `sync_pair_busy` while the job waits. A pruned record now logs a `Deleted target record` event. `p202 sync` gives each new code its next step.
