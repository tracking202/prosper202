# 6FZ9: Library records say where they are used and, for landing pages, how their code check stands.
-- New: The v3 lists of campaigns, affiliate networks, traffic sources, traffic source accounts, landing pages and text ads take with=usage, which adds to each row how many of the account's live records point at it, by kind (links, landing pages, text ads, rotators by default or by any rule's redirect, offers, traffic source accounts, ad connections) and in total; the landing page list also takes with=health, the page's stored code check for its present URL or status unchecked. GET /<resource>/{id}/uses names those records, the first 25 of each kind, and a delete's dry run carries the same as in_use_by, since a soft delete leaves them pointing at the deleted record. Another account's rows never count, an unknown with, an empty item or a repeat is a 422 naming with, and the fields are opt-in so rows read for a PUT body are unchanged.
app: New: The API can say where each offer, network, traffic source, landing page and text ad is used, and a delete preview lists them.
