# 6W9E: every curl option is set through one helper that refuses the request when curl will not take a value.
-- Fixed: An outbound request no longer goes out without part of its settings. About 240 places that set curl options read nothing back, and curl answers false for a value it will not take (a negative or too large time limit, an unknown proxy type, a size cap below zero); setting a list of options also stopped at the refused one and left the rest unset, the URL, the time limits and the size cap included. Every option is now set through Prosper202\Http\CurlOptions::set(), which stops at the first refused option and names it. A request to a fixed host (my.tracking202.com, the licence and ClickServer calls, the app stores, Google Play Integrity, IPQualityScore, exchange rates, Messaging, Chat Pass, the Landing Page Optimizer) is then not sent and answers as an unreachable service does, with the option logged; the webhook, postback, sync, landing page check and GeoIP download senders report it as their own failure; the report rebuild counts the hour's request as failed, so its window is released and retried; and the PHP CLI says the request was not sent. CurlOptionsAreCheckedTest refuses a curl_setopt() anywhere else in the tree.
