-- New: Every webhook Prosper202 sends (LTV webhooks and attribution export webhooks) is signed the Standard Webhooks way: webhook-id (stable across retries), webhook-timestamp (the attempt's time) and webhook-signature (v1, the base64 HMAC-SHA256 of id.timestamp.body), so a receiver verifies it with a Standard Webhooks library. New secrets are whsec_ secrets; a secret from before 1.9.81 is signed with its own bytes, which a library takes as whsec_ followed by its base64.
app: New: Webhooks are signed the Standard Webhooks way (webhook-id, webhook-timestamp, webhook-signature), so any Standard Webhooks library can verify them.
-- New: LTV webhook bodies are the envelope {type, timestamp, data, id}, with versioned event types (revenue.recorded.v1); the older event and occurred_at keys stay beside them while X-P202-Signature is sent.
-- New: An LTV webhook's secret can be rotated (POST /ltv/webhooks/{id}/rotate-secret, p202 ltv webhooks rotate-secret, ltv:webhook:rotate-secret, and Rotate secret in LTV Settings). For overlap_hours (default 24, up to 168) deliveries are signed by the old secret too, so the receiver changes over without a delivery failing. The Landing Page Optimizer's webhook is not rotated: connecting the optimizer again gives it a new secret.
app: New: Rotate an LTV webhook's signing secret, with the old one still signing for a day while the receiver changes over.
-- Changed: X-P202-Signature (and an export's X-P202-Timestamp) is deprecated. 1.9.81 and 1.9.82 send it beside the Standard Webhooks headers; 1.9.83 stops. LTV webhooks' X-P202-Signature carries no timestamp, so it can be replayed: move receivers to webhook-signature.
app: Changed: X-P202-Signature is deprecated and stops in 1.9.83; verify webhook-signature instead.
