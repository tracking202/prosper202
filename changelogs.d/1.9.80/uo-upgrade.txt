-- Changed: An upgrade that stops now says so on the page: the version the database stands at, that running it again is safe and carries on from there, what to do about the cause it recognises (the database user may not change tables, the server is out of space, a lock did not clear, the connection was lost), and a copyable report of each step and statement that failed. The report holds no value a statement quoted and not the database's name, as the page is shown before sign-in; the server's PHP error log keeps the full lines. Both 1-Click Upgrade pages add the same report to their log when the database step fails. An upgrade that loses its connection to the database now gets the same report, saying the version could not be read, where it used to end on the database error page. On the 1-Click Upgrade pages that case shows the log on a page of its own, with the way to run the database upgrade again. A date the upgrade page could not read now says which format it wants instead of "an unexpected error".

After a download that failed, the page says whether trying again can help (the update server was slow, silent or failing) or not (a refused download, a signature or version that does not match).
