-- New: Postbacks and pixels can be authenticated. Click ids count up, so anyone who guessed one could record or reverse a conversion through pb.php, gpb.php, px.php, gpx.php or upx.php. Each account now has a postback token that every pixel and postback URL from Setup › Postback / Pixel, GET /conversions/postback-code and `p202 conversion postback-url` / `pixel` carries as p202_token; when the account requires it, a request without the token or a signature is refused 403 and nothing is recorded, and a wrong token is refused either way. A sender that can compute an HMAC can sign instead (p202_ts + p202_sig, HMAC-SHA256 over the endpoint and the sorted query, 300 s window), so the token never travels. Accounts from before 1.9.80 start with the requirement off; copy the URLs again, give them to your networks, then turn it on under Account › API Integrations › Postback authentication (or `p202 conversion postback-auth set --token-required 1`). New accounts start with it on. The token rotates with a grace period for the old one (`p202 conversion postback-auth rotate`, POST /conversions/postback-auth/rotate). A pixel's token can be read on the advertiser's page, so it stops blind guessing rather than someone who has seen the page.
app: New: Postbacks and pixels can require your account's postback token or a signature, so a guessed click id no longer records or reverses a conversion. Turn it on under Account › API Integrations once your networks have the new URLs.
