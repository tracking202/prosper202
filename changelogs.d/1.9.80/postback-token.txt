-- New: Postbacks and pixels can be authenticated. Click ids count up, so anyone who guessed one could record or reverse a conversion through pb.php, gpb.php, px.php, gpx.php or upx.php. Each account now has a postback token, which every pixel and postback URL from Setup › Postback / Pixel, GET /conversions/postback-code and `p202 conversion postback-url` / `pixel` carries as p202_token, and a signing secret, which no URL carries: a sender that can compute an HMAC signs each request with p202_ts + p202_sig (HMAC-SHA256 keyed with the secret over the endpoint and the sorted query, 300 s window). Each account chooses what its postbacks and pixels must carry: off (accepted without; a wrong token or signature is still refused), token (the token or a signature) or signed (a signature only: the token alone is refused, and so is every pixel, which a browser cannot sign). Refusals answer 403 and record nothing. Accounts from before 1.9.80 start at off: copy the URLs again, give them to your networks, then choose token under Account › API Integrations › Postback authentication (or `p202 conversion postback-auth set --mode token`); new accounts start at token. The token and the secret each rotate with a grace period for the old one (`p202 conversion postback-auth rotate`, POST /conversions/postback-auth/rotate). The token and the secret are given only to an API key that may write conversions (conversions:write): GET /conversions/postback-auth asks for it, and GET /conversions/postback-code answers a read-only key the URLs without the token (postback_token_withheld says why). The rotation honors Idempotency-Key. A token or secret that cannot be read (its key lost from the database) refuses a request that presents it with 500 while the mode still decides one that presents nothing, and is replaced with a new one, said so, by the Account and Setup pages, the API's postback-auth routes and a rotation. A pixel's token can be read on the advertiser's page, so it stops blind guessing rather than someone who has seen the page; signed mode is for senders that sign.
app: New: Postbacks and pixels can require your account's postback token, or only signed postbacks, so a guessed click id no longer records or reverses a conversion. Choose under Account › API Integrations once your networks have the new URLs.
