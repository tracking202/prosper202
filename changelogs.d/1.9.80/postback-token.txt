-- New: Postbacks and pixels can be authenticated: once an account requires it, pb.php, gpb.php, px.php, gpx.php and upx.php refuse a request that carries neither the account's token nor a valid signature. Each account now has a postback token, which the pixel and postback URLs from Setup › Postback / Pixel, GET /conversions/postback-code and `p202 conversion postback-url` / `pixel` carry as p202_token (a read-only API key gets them without it, below), and a signing secret, which no URL carries: a sender that can compute an HMAC signs each request with p202_ts + p202_sig (HMAC-SHA256 keyed with the secret over the endpoint and the sorted query, 300 s window). Each account chooses what its postbacks and pixels must carry: off (everything accepted, a stale token too), token (the token or a signature) or signed (a signature only: the token alone is refused, and so is a pixel that is not signed, as a browser cannot sign). A refused request records nothing: pb.php, gpb.php, px.php and upx.php answer 403, and gpx.php, which has already sent its image, logs the refusal. Accounts from before 1.9.80 start at off: copy the URLs again, give them to your networks, then choose token under Account › API Integrations › Postback authentication (or `p202 conversion postback-auth set --mode token`); new accounts start at token. The token and the secret each rotate with a grace period for the old one (`p202 conversion postback-auth rotate`, POST /conversions/postback-auth/rotate). The token and the secret are given only to an API key that may write conversions (conversions:write): GET /conversions/postback-auth asks for it, and GET /conversions/postback-code answers a read-only key the URLs without the token (postback_token_withheld says why). The rotation honors Idempotency-Key. Under token and signed, a token or secret that cannot be read (its key lost from the database) refuses a request that presents it with 500 while the mode still decides one that presents nothing, and off accepts both; such a credential is replaced with a new one, said so, by the Account and Setup pages, GET and PUT /conversions/postback-auth and a rotation. Anyone who sees a page with a pixel can read its token, so for senders that can sign, signed mode is the stronger choice.
