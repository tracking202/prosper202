-- New: Postbacks and pixels can be authenticated, so only your own networks and pages can record or reverse a conversion through pb.php, gpb.php, px.php, gpx.php or upx.php. Each account now has a postback token, which every pixel and postback URL from Setup › Postback / Pixel, GET /conversions/postback-code and `p202 conversion postback-url` / `pixel` carries as p202_token, and a signing secret, which no URL carries: a sender that can compute an HMAC signs each request with p202_ts + p202_sig (HMAC-SHA256 keyed with the secret over the endpoint and the sorted query, 300 s window). Each account chooses what its postbacks and pixels must carry: off (everything accepted, a stale token too), token (the token or a signature) or signed (a signature only: the token alone is refused, and so is every pixel, which a browser cannot sign). Refusals answer 403 and record nothing. Accounts from before 1.9.80 start at off: copy the URLs again, give them to your networks, then choose token under Account › API Integrations › Postback authentication (or `p202 conversion postback-auth set --mode token`); new accounts start at token. The token and the secret each rotate with a grace period for the old one (`p202 conversion postback-auth rotate`, POST /conversions/postback-auth/rotate). The token and the secret are given only to an API key that may write conversions (conversions:write): GET /conversions/postback-auth asks for it, and GET /conversions/postback-code answers a read-only key the URLs without the token (postback_token_withheld says why). The rotation honors Idempotency-Key. A token or secret that cannot be read (its key lost from the database) refuses a request that presents it with 500 while the mode still decides one that presents nothing, and is replaced with a new one, said so, by the Account and Setup pages, the API's postback-auth routes and a rotation. A pixel's token is visible on the page that carries it; signed mode, for senders that sign, accepts signatures only.
app: New: Require your account's postback token or a signature on every postback and pixel, so only your own networks can record or reverse a conversion. Choose under Account › API Integrations once your networks have the new URLs.
