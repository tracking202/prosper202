# DT30: each API key's last use, and Replace.
-- New: My Account › Personal Settings › API keys shows when each key was last used, on which API version, and what the client called itself (its User-Agent), so you can tell which script or app a key belongs to before you revoke it. The time is recorded from 1.9.80 on, at most once every five minutes per key, on the v1, v2 and v3 APIs; a key shows "No use recorded" until its first request after the upgrade. GET /api/v3/users/{id}/api-keys and `p202 user apikey list` carry the same as last_used_at, last_used_api and last_used_client.
app: New: Each API key shows when it was last used and by what, so you can tell which integration holds it.
-- New: Replace on an API key makes a new key with the same access and label, shows it once, and lets the old key keep working for 24 hours so you can switch without an outage. The old key's row says when it ends; Revoke ends it at once. After that the old key is refused with a message saying it was replaced, where a revoked key is only "Invalid API key". The key list in the API shows the ending as ends_at. A replaced key stays in the list for seven days after it ends and is then removed by the hourly cron job. An AI app's key is replaced by connecting the app again.
app: New: Replace an API key from My Account: the new key is shown once and the old one keeps working for 24 hours.
-- Changed: `p202 user apikey rotate` replaces a key the same way, through the new POST /api/v3/users/{id}/api-keys/replace: the new key carries the old key's scope and label, and the old key works for 24 hours more. It no longer deletes the old key, and no longer takes --scope or --keep-old (it says what to run instead); `p202 user apikey delete` ends a key at once. Against a server older than 1.9.80 it says to create a key and delete the old one.
app: Changed: `p202 user apikey rotate` gives the old key 24 hours, as Replace does; `apikey delete` ends a key at once.
-- New: A new API key can be named when it is made in My Account, for what will use it. The name shows on the key's row and carries over when the key is replaced.
app: New: Name an API key when you make it, so you can tell your keys apart.
