-- New: A click that IPQualityScore filtered says so. Visitors and Spy show why each filtered click was filtered (fraud score, your sign-in address, a crawler range, a repeat visit, your filter list), and a Show select above the list lists only the clicks filtered for one reason (?filter_reason=). A click filtered for its fraud score has a Not fraud button: the click, and your other clicks from the same address that were filtered for their score, count again in every report, and the address goes on your click filter list as always count, so it is not scored again; POST /api/v3/clicks/{id}/not-fraud and `p202 click not-fraud <id>` do the same, and the click filter's own routes and commands list and remove the address. Scoring passes over any address the list says always counts. The IPQualityScore card on Account > API integrations says how many addresses were scored and how many clicks were filtered in the last 24 hours.
app: New: Visitors shows why a click was filtered, and a click IPQualityScore filtered has a Not fraud button that counts it again.
-- Changed: A landing page URL written without http:// or https:// (lp.example.com/x, //lp.example.com/x) is saved with https:// instead of refused, the leave-behind URL too: Setup > Landing Pages says so on the page, and POST and PUT /api/v3/landing-pages say so in the answer's meta.normalized (what was sent, what is stored). Anything else that does not start with http:// or https:// is still refused. Sync (POST /api/v3/sync and `p202 sync`, `p202 diff`) compares landing pages on the stored form, so a source that still holds a URL without its scheme matches the one page it made on the target however often it is synced; a `p202` binary older than this release does not, so update it before syncing such a source. Landing page URLs stored without a scheme by an earlier version are given https:// by the upgrade; one that would not fit the column is left as it is. Setup > Landing Pages' save is one prepared transaction now: a page and its public id are written together or not at all, and a campaign or page id that is not a whole number is refused.
app: Changed: A landing page URL typed without https:// is completed for you instead of refused.
-- New: The landing page code check runs without being asked and its answer is kept. Setup > Landing Pages shows each page's answer beside it (code found, not found, another page's code, commented out, loaded from another tracker, could not be checked), checks a page that has no answer for its present URL when the list opens, and has a "check code" link to ask again; the cron job checks each page again about once a day, so a page that loses its code says so. Get LP Code shows the last answer under Check my page. POST /api/v3/landing-pages/{id}/check, `p202 landing-page check <id>` and the landing_page_check MCP tool run the same check; a read-only key may use them, since the check changes no setup. The fetch is held to the rules it was: public addresses only, each redirect checked, 10 seconds and 2 MB at most.
app: New: Landing Pages shows whether each page carries its tracking code, and checks it for you.
-- Changed: Update Subids reads a payout written with your account currency's sign or code ("$12.50", "12.50 USD", "US$ 12.50") as its number, on a line and in the Payout field, and says which it read; POST /api/v3/conversions/subids does the same and answers the written form as payout_written. A pasted network report no longer has every line refused for its sign. Another currency's sign is still refused, since the amount is recorded in the account's currency, and so are a thousands separator and a decimal comma.
app: Changed: Update Subids accepts payouts pasted with a currency sign, such as $12.50.
