-- Fixed: The global postback (tracking202/static/gpb.php) read its parameters from the query string only, so a network that sent subid (or sid), amount and the order number in a form-encoded POST body, as paid 1.9.56 accepted, was answered "SubID not found" and the sale was not recorded. A form-encoded POST body is read again: the query string wins a name both carry with a value, and the body fills a name the query leaves out or blank, so a postback URL pasted as gpb.php?amount=&subid= with the values in the body records the sale.
app: Fixed: The global postback records sales sent in a form POST body again, as paid 1.9.56 did.
-- Changed: Upgrading from paid 1.9.56: on a form POST to the global postback, 1.9.56 read subid and sid from the body only; now a value for either in the postback URL's query string is used and the body's subid and sid are ignored. Remove a fixed click id or an unfilled macro such as subid={subid} from a URL that a network POSTs to, or the sale goes to that click or is answered "SubID not found". The same holds for the order number, customer and product names: a value in the query string keeps all of the body's names for it out.
app: Changed: From paid 1.9.56: on a form POST to the global postback, a subid or sid in the URL is used instead of the body's.
