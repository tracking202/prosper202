# CA14: REST API keys stored as a hash and matched exactly.
-- Changed: Prosper202 stores each REST API key as a SHA-256 hash and its first 8 characters, not the key itself, so a copy of the database holds no usable key. A key is shown once, when it is made: in My Account › Personal Settings › API keys, in the answer to POST /api/v3/users/{id}/api-keys, and on the installer's last page. The Reveal and Copy buttons on existing keys are gone; a key you did not save can be replaced by making a new one and revoking the old. Integrations keep working: the p202 command line, AI apps connected through Tracking202's MCP server and your scripts each hold their own copy and send it as before. The upgrade to 1.9.80 hashes every key already stored.
app: Changed: API keys are stored as a hash and shown once, when made; Reveal and Copy are gone, and every key keeps working.
-- Fixed: An API key is matched character for character. It was looked up without regard to case, so a key typed with its letters in the other case was accepted. Keys made by Prosper202 are lower-case hex and are not affected; a key someone chose with mixed case now works only as typed.
app: Fixed: An API key is accepted only exactly as made, letter case included.
-- Changed: Upgrading to 1.9.80: once the upgrade has hashed the API keys, putting back 1.9.79 or earlier files stops every API key working, AI app connections included, since older versions look for the key itself. To go back, restore the database backup taken before the upgrade, or make new keys after going back.
app: Changed: After the 1.9.80 upgrade, going back to an older version needs the pre-upgrade database backup or new API keys.
