-- Fixed: A redirector rule whose country was saved as a bare code ("US") or whose device was saved with a capital ("Mobile") never matched a visitor, and 1.9.80 had refused to save a redirector holding one until each value was corrected by hand. Such a value is now saved in the form the redirects match: a country typed as its code or its name becomes Name(CC) ("United States(US)") and a device is lowered, by one normalizer (Prosper202\Rotator\Criterion::stored()) for Setup › Redirectors and the API; the page says what it changed, and the API answers it as meta.normalized. Rules already stored need no change: the redirects (rtr.php, offrtr.php) now match a country by its code, whatever name the GeoIP database gives it, and a device in any case, so a rule stored as "US", "Mobile" or under a country's former name matches its visitors, and "is not US" no longer matches everyone.
app: Fixed: A redirector rule saved as "US" or "Mobile" now matches its visitors, and typing a country's code or name saves it in the right form instead of refusing the save.
-- New: Setup › Redirectors suggests a rule's value as it is typed for every link value: c1-c4, the keyword, the referer's host and the five UTM values are suggested from what the account's own clicks carried (its newest 50,000 of the last 30 days), the busiest first, and a country from a built-in list by code or name, with no call to a hosted service.
app: New: Redirector rules suggest the UTM, c1-c4, keyword and referer values your own clicks carried as you type.
-- New: A redirector rule that sends no visitor anywhere is called out where it is made. Setup › Redirectors marks the rule in the list and beside the criterion in the editor, as soon as the type is chosen: a "High fraud score" rule on an account with no IPQualityScore key saved (with the way to the setting) or whose privacy setting holds every visitor back, an ISP rule without the MaxMind ISP database, a country value with no code, a region or city without its (CC), a value outside a fixed set, a type or statement the redirects do not read, and a rule that comes after an active rule matching every visitor. The API answers the same as meta.warnings on every rule write and on GET /rotators/{id}. A refusal on the page now marks the criterion it names.
app: New: Setup › Redirectors warns when a rule can never match, such as a fraud rule with no IPQualityScore key or a rule placed after one that takes every visitor.
-- Fixed: A redirector's "Device type is desktop" rule matched no Mac, and "is bot" no crawler: rtr.php and offrtr.php compared the user agent parser's own device name ("Mac", "Spider") wherever it was not "Other". Both now name the device as the click is recorded (Prosper202\Rotator\VisitorDevice): Tablet, Mobile, Bot or Desktop. Setup › Redirectors offered or withheld the ISP rule type by the first account's MaxMind ISP setting; it follows the account's own, the one its redirects read.
app: Fixed: A redirector's "desktop" device rule now matches Macs, and the ISP rule type follows your own account's MaxMind ISP setting.
