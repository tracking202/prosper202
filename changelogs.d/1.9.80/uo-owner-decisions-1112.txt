-- Changed: POST /landing-pages/{id}/check (`p202 landing-page check`, the MCP tool landing_page_check) answers a page checked in the last 30 seconds from that check, with `fetched: false`, `checked_at`, `fetch_again_in_seconds` and a note, instead of fetching it again, and each API key may have 10 pages fetched a minute (a fixed window from its first fetch), counted by the key and not by any header. Past that the answer is a 429 with Retry-After and a message saying when to try again, nothing is fetched, and the CLI's hint names the wait and the command to run again. A read-only key may still check a page. The Check my page button and the checks Setup › Landing Pages makes, which a signed-in session sends, are not limited.
-- Changed: The Shopify refunds left to settle can be seen, recorded and closed by a role with access to Account › API Integrations, the one that runs the Shopify connection, as well as by a role with the Setup and Update sections; a role with Setup alone still sees them. One rule answers for Setup › Inbound Log, GET /conversions/shopify-refunds and its record and close routes, and `p202 conversion shopify-refunds`. A role without Setup reaches the refunds from the Shopify card and is shown only them on the Inbound Log page, with no Setup menu and no log.
-- Changed: The Go CLI reports an HTTP 429 as its own category, `rate_limited`, with exit code 7, instead of an input error (exit 1): nothing in the request is wrong. The `--json` error envelope carries `retry_after_seconds` (from the answer, or its Retry-After header), and the hint names the wait and says to run the same command again. `sync --skip-errors`, `conversion import` and `import` stop at a 429 instead of sending every later record into it, and `import` names the records still to send (the whole file again would create the first ones twice); a shell batch or `exec` whose every failure was a 429 exits 7 and names what to run again, and a `shell --stop-on-error` batch stopped after earlier commands ran names the commands left to run; an `import` stopped after `--skip-errors` went past refused records names them and their errors, and a record whose create failed with a 5xx or on the connection is named as one that may exist already; an import file item that is not an object is refused naming it, where it was skipped and shifted every later record's number; and the Google Ads destination commands give the wait rather than their connect hint.
