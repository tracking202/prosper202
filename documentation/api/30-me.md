# Me

Who is signed in, and what they may see and do.

| Method | Path | Auth | Description |
| ------ | ---- | ---- | ----------- |
| `GET` | `/me` | Bearer | The caller's user, account, roles, permissions, flags, switches, install version and features |

`GET /me` is the one read a client makes to decide which screens, buttons and
money figures to show. Any valid key reads it, whatever its scope or role, so a
role that may not read `GET /system/version`, which asks for Admin and
Settings, still learns the install's version here.

```json
{
  "data": {
    "user": { "user_id": 3, "user_name": "sam", "user_email": "sam@example.com", "user_fname": "Sam", "user_lname": "Lee" },
    "account": { "timezone": "Europe/Berlin", "currency": "EUR" },
    "roles": [ { "role_id": 4, "role_name": "Campaign optimizer" } ],
    "permissions": ["access_to_campaign_data"],
    "flags": {
      "is_admin": false,
      "can_manage_admins": false,
      "can_see_money": true,
      "can_view_setup": false,
      "can_edit_campaigns": false,
      "can_delete_campaigns": false,
      "can_use_update_section": false,
      "can_delete_subids": false,
      "can_view_attribution": false,
      "can_manage_attribution": false,
      "can_edit_personal_settings": false,
      "can_manage_users": false,
      "can_view_settings": false,
      "can_use_api_integrations": false,
      "can_see_vip_perks": false
    },
    "scopes": ["*"],
    "switches": { "licence": "licensed", "sponsored_ads": "show_all" },
    "install": { "version": "1.9.81", "schema_version": "1.9.81", "api_version": "v3" },
    "features": ["api_key_scopes", "create_idempotency", "delete_dry_run", "staged_writes", "..."],
    "auth": { "method": "api_key", "csrf_token": null }
  }
}
```

## Fields

- `account.timezone`: the named zone the reports read hours and days in
  (`user_timezone`); `UTC` when unset or not a zone PHP knows.
- `account.currency`: the code the account's money is printed in
  (Personal Settings' currency); `USD` when unset.
- `permissions`: every role permission the user holds, sorted. The flags are
  derived from these.
- `flags`: the gates the web pages and the API routes apply. A flag is true
  only when the routes behind it answer this caller: where a route also asks
  the key for a scope, the flag asks it too, so a read-only key's
  `can_edit_campaigns` is false whatever the role allows. With `can_see_money`
  false, reports, clicks and conversions come back with clicks, leads and
  money masked (`masked: true`), as the report pages print them as `?`.

| Flag | Role permission | Key scope |
| ---- | --------------- | --------- |
| `is_admin` | Admin or Super user role | |
| `can_manage_admins` | Admin role and `add_edit_delete_admin` | `users:write` |
| `can_see_money` | `access_to_campaign_data` | |
| `can_view_setup` | `access_to_setup_section` | `campaigns:read` |
| `can_edit_campaigns` | `access_to_setup_section` | `campaigns:write` |
| `can_delete_campaigns` | `access_to_setup_section` and `remove_campaign` | `campaigns:write` |
| `can_use_update_section` | `access_to_update_section` | `conversions:write` |
| `can_delete_subids` | `access_to_update_section` and `delete_individual_subids` | `conversions:write` |
| `can_view_attribution` | `view_attribution_reports` | `attribution:read` |
| `can_manage_attribution` | `manage_attribution_models` | `attribution:write` |
| `can_edit_personal_settings` | `access_to_personal_settings` | `users:write` |
| `can_manage_users` | Admin role and `add_users` | `users:write` |
| `can_view_settings` | Admin role and `access_to_settings` | `system:read` |
| `can_use_api_integrations` | `access_to_api_integrations` | |
| `can_see_vip_perks` | `access_to_vip_perks` | |

- `switches.licence`: what the licence-gated surfaces (the Go CLI, connecting
  an AI assistant) answer now, as `cli` in [capabilities](17-capabilities.md):
  `licensed`, `not_licensed`, or `unconfirmed` when Tracking202 gave no answer
  within the grace period. When the install cannot read whose key counts (its
  own lookup fails), the gates let the CLI through, and this says `licensed`.
- `switches.sponsored_ads`: Personal Settings' ad setting, `show_all`,
  `hide_login` or `hide_all`.
- `install.version` is the code's version; `install.schema_version` the
  version the database was last upgraded to (`unknown` without a version row).
- `features`: the names of the features [capabilities](17-capabilities.md)
  advertises as on.
- `auth.method` is `api_key`, and `auth.csrf_token` is null for a key.
